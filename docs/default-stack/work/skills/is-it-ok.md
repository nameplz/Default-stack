# is-it-ok

구현된 코드를 별도 검증 세션에서 검증한다. 실패 시 [shall-we](shall-we.md)로 돌아간다.

## 입력

검증 서브에이전트에 아래 항목을 명시적으로 전달한다 ([decisions.md](../../decisions.md)).

- 문제 정의 ([whats-wrong](whats-wrong.md) 산출물)
- 관련 문서
- Git diff
- 테스트 결과

## 검증 관점

| 관점 | 확인 내용 |
|---|---|
| Spec | 완료 조건 충족, non-goals 위반, 과잉·불필요 구현 |
| 구조 | 설계·품질 문제 |
| 실행 | 테스트, 빌드, 런타임 실행. 실행 가능하면 실제로 실행해 결과 확인 |

테스트를 약화시키는 변경도 확인한다: `.skip` 추가, 기존 테스트 삭제, assertion 완화, lint·타입 검사 억제 주석.

## 판정

- 통과 / 실패 / 미확인 세 가지.
- 실제 증거 없는 통과 금지.
- 실제로 확인한 것과 확인할 수 없었던 것을 구분해 보고한다.
- 낮은 심각도의 스타일 선호를 실제 결함과 같은 수준으로 다루지 않는다.
