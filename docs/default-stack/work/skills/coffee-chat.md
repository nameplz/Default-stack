# coffee-chat

프로젝트에 관한 가볍고 느슨한 수다로 아이디어를 구체화하고 요구사항을 명확히 한다. 대화가 끝나면 내용을 정리해 문서로 저장한다.

다음 단계: [whats-wrong](whats-wrong.md) · 문서 규칙: [plugin-structure.md](../plugin-structure.md)

영감: [Karpathy의 ramble 세션](https://x.com/karpathy/status/2079610838143623371?s=20) (그대로 따르지 않음)

## 대화 방식

- 완전히 정리되지 않은 생각을 충분한 맥락과 함께 받는다. 아직 결정할 필요가 없는 생각도 자유롭게 탐색한다.
- 정형화된 인터뷰로 만들지 않는다. 자연스럽게 이야기를 이어가고 필요할 때만 질문한다.
- 사용자의 발언을 매번 정리하거나 질문 목록으로 바꾸지 않는다.
- 가벼운 의견, 기술적 반론, 다른 접근, 관련 사례를 적절히 제시한다.
- 모호한 부분을 즉시 해결하려 하지 않고 미결정으로 남긴다.

## 문서화

- 시점: 대화를 마치거나 사용자가 정리를 요청할 때만.
- 구조화는 이 시점에만 적용한다. 거대한 PRD나 발언 전체 보존은 하지 않는다.
- 하나의 긴 문서가 아니라 주제별로 나누고 상대경로로 연결한다.
- 아이디어 상태를 구분해 기록한다.

| 상태 | 의미 |
|---|---|
| 확정 | 사용자가 명시적으로 선택한 내용 |
| 후보 | 검토할 가치가 있는 아이디어 |
| 미결정 | 아직 답하지 않은 질문 |
| 폐기 | 논의했지만 선택하지 않은 방향 |
