# whats-wrong

관련 자료를 리서치한 뒤, 요구사항을 직접 충족하는 niche하고 clutch한 문제를 정의하고 Phase/Step으로 분할해 문서화한다.

이전: [coffee-chat](coffee-chat.md) · 다음: [shall-we](shall-we.md)

## 절차

1. 리서치에 반드시 포함할 항목을 먼저 정한다.
2. 리서치를 진행하고 `research/`에 주제별로 저장한다. 깊이는 프로젝트 규모에 비례하되, 가벼운 리서치도 결과는 항상 문서로 남긴다.
3. 문제를 정의한다.
4. 큰 덩어리(Phase)로 나누고, 각 덩어리를 작은 단위(Step)로 나눈다.
5. `work/`에 주제별로 나누어 저장하고 상대경로로 연결한다.

## 문제 기준

| 기준 | 의미 |
|---|---|
| Niche | 문제의 대상, 발생 조건, 영향받는 사용자 경험·기능이 구체적으로 식별됨 |
| Clutch | 해결하면 요구사항 충족이 직접 개선되고, 주변 작업은 최소 |

## Phase/Step

- 사용자에게 실제로 동작하는 작은 기능 단위로 구성한다.
- Phase는 목적이나 완료 조건이 서로 다를 때만 나눈다.
- Step은 독립적으로 구현·검증할 수 있는 최소한의 의미 있는 단위다.
- 파일이나 기술 계층만을 기준으로 분해하지 않는다.
- 각 Step에 완료 조건과 선행 작업을 기록한다.
- 규모가 작으면 Phase 1개, Step 1개로 끝내도 된다.

## 종료 조건

문서 작성 완료가 아니라, 다음 단계에서 추가 추측 없이 구현을 시작할 수 있을 만큼 문제가 정의되었는지로 판단한다.
